# MedicalChannelAI Zero-Config Trial v0.1

Status: **SUPERSEDED_2026-08-30**

本方案已被产品负责人否决，不再作为天津 Pilot 的执行方向。

## 被替代的原因

天津 Pilot 的核心不是给客户看一个通用商机榜单，而是验证：

> 客户把自己的医院关系、产品能力、厂家/渠道/租赁资源告诉系统后，MedicalChannelAI 能否每天真正替他判断最值得跟的项目，并用 Agnes 给出有依据的下一步销售动作。

因此“先零录入使用几天，再决定是否填写资料”的路线会弱化产品最重要的个性化价值，也无法真实验证 Agnes 决策链。

## 当前冻结方向

以后实现和验收统一以以下原则为准：

1. 首次 Pilot 登录后直接进入轻量客户画像录入；
2. 只录影响商机判断的关键信息，不建设复杂 CRM；
3. 至少包括：经营区域、客户类型、产品/品类能力、品牌或厂家资源、医院关系、渠道合作能力、租赁能力、最低项目金额和关注阶段；
4. 用户确认的数据必须标记为客户私有事实，绝不能混入官方采购事实；
5. 保存画像后，`/today` 立即使用新画像重新做确定性匹配和优先级排序；
6. 只有最终入选且满足 grounded 条件的最多 5 个候选进入 Agnes 队列；
7. Agnes 通过服务端 Worker 调用，浏览器不得持有 API Key、模型名、供应商地址或内部任务信息；
8. Agnes 输出必须通过既有 allowlist、grounding 和事实引用校验后，才能成为 `READY` 建议；
9. 后续每天继续复用同一画像自动筛选，无需重复填写；
10. 用户可随时修改画像，修改后重新匹配并产生新的受控 Agnes 决策；
11. `production_ready=false`，真实 Pilot 验证完成前不得自行 merge。

## 当前用户路径

`一次性邀请登录 → 我的资料 → 保存 → 今日行动 → Top5 → Agnes 排队/校验 → READY 销售动作 → 跟进记录`

## 日更要求仍然有效

个性化不替代公开数据更新。真实 Pilot 仍必须持续做到：

- 自动发现新增/变更的医疗采购公开信息；
- 事实验证后进入可信索引；
- 每天按客户画像重新匹配；
- 页面显示真实刷新状态与覆盖警告；
- 不得把冻结快照、失败抓取或演示数据冒充实时全量数据。

后续开发不得再恢复 `ZERO_CONFIG_TRIAL` 作为默认产品路径，除非产品负责人明确重新决定。
