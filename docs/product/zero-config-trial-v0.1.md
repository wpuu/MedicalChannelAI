# MedicalChannelAI Zero-Config Trial v0.1

Status: FROZEN_FOR_TIANJIN_PILOT

## 目标

第一次给医疗渠道客户使用时，不要求先录医院关系、品牌、厂家、产品线或联系人。

用户打开 `/today` 就应该先看到：

1. 今天新出现或仍处于可介入窗口的医疗采购机会；
2. 最多 5 个重点项目；
3. 官方事实与官方依据；
4. 为什么现在值得看；
5. 今天可以做的下一步动作；
6. 哪些判断仍需要客户本人确认。

客户画像是后续增强项，不是首次使用门槛。

## 两阶段产品模式

### A. ZERO_CONFIG_TRIAL

无需客户资料。

系统只允许使用：

- VERIFIED / 可追溯公开采购事实；
- 明确医疗相关的项目分类；
- 公告日期、报名/投标截止时间、预算、采购阶段；
- 官方来源 URL；
- 通用天津医疗渠道场景配置。

系统不得声称知道客户真实医院关系、厂家授权、品牌能力或院内需求。

通用场景中的客户侧字段必须标记为 `DEMO/GENERIC_CONTEXT`，不能伪装为客户确认事实。

### B. PERSONALIZED

客户确认产品、医院关系、厂家/渠道/租赁能力后，才允许使用这些信息重新匹配、重新排序并生成个性化行动建议。

## 试用期产品承诺

首页主价值：

> 不需要先录资料。每天先告诉你今天有哪些医疗项目值得看、官方依据是什么、下一步先做什么。

个性化价值：

> 觉得有用后，再补充你的医院关系和产品资源，系统会把通用商机变成更适合你的商机排序和行动建议。

## 日更要求

零配置试用能否成立，取决于“每天内容真的变化”，而不是静态 Demo。

因此天津 Pilot 的下一优先级是：

1. 自动发现新增/变更的医疗采购公开信息；
2. 经过事实验证后进入 VERIFIED index；
3. 每日重新生成最多 5 个 Today Actions；
4. H5 显示数据刷新时间；
5. 公开来源覆盖不完整时继续显示 coverage warning；
6. 不得把冻结快照或失败抓取伪装成实时数据。

## 演示期允许的过渡方式

在完整自动日更上线前，可以使用“人工/半自动生成的 VERIFIED 日快照”部署到 H5，但必须满足：

- 每条项目有官方依据 URL；
- 页面显示真实快照时间；
- 明确说明客户资源是演示/通用场景；
- 不得声称已接入实时全量天津采购数据。

## 排序边界

ZERO_CONFIG_TRIAL 阶段可以使用通用场景帮助筛选医疗相关项目，但不得把通用场景中的关系/产品能力描述成客户事实。

正式 Personalized 排序继续沿用：

- 产品执行能力 30
- 客户确认关系 25
- 介入阶段 25
- 项目金额 20

“经营优先级”始终不等于中标概率。

## 当前执行顺序

1. 保持 `medicalchannelai.vercel.app` 作为天津 Pilot 演示地址；
2. 生产 H5 先采用零配置试用文案；
3. 接每日 VERIFIED 数据刷新；
4. 让老杨连续使用几天，观察他是否会主动点项目、打开官方依据、生成话术、标记跟进；
5. 只有确认有价值后，再让他补少量真实医院关系/产品资源；
6. 再比较个性化前后的排序是否明显更有用。
