# MedicalChannelAI 商务 Demo

状态：`DEMO_ONLY / SYNTHETIC_DATA`

目标：第一次给医疗渠道客户看时，不讲爬虫、模型路由、Schema 或后台架构，只证明一件事：

> 系统能把“公开采购项目 + 客户自己的医院关系/产品能力”变成今天该做什么。

## 推荐访问地址

优先：

1. `https://medradar.qzz.io/`
2. `https://medicalai.qzz.io/`
3. `https://medradar.dpdns.org/`

实际名称以 DigitalPlat Domains 注册时可用为准。

## 演示前

1. 确认页面右上角显示“演示数据”，不是“天津 Pilot”。
2. 点击“重置演示”，恢复所有跟进状态。
3. 确认顶部出现“虚构演示客户画像”。
4. 不使用真实医院、真实联系人或真实客户关系冒充 Demo 数据。

## 5分钟演示路径

### 1. 先看客户画像（约30秒）

说明：

- 同一批公开采购项目，对不同经销商/厂家价值完全不同；
- 系统先知道客户有哪些医院关系、产品能力、能否找厂家/联合渠道；
- 所以下面的 TOP5 是“这个客户今天最值得跟的”，不是普通招标搜索排名。

### 2. 打开 TOP1（约1分钟）

重点看三块：

- 官方/已验证事实；
- 我的资源；
- AI行动建议。

说明经营优先级只用于安排销售资源，不是中标概率。

### 3. 点“生成沟通话术”（约1分钟）

说明正式版不是让 AI 自由编医院事实，而是根据已核实公开事实 + 客户确认资源按需生成，并要求人工确认。

Demo 中的话术明确标记为演示草稿。

### 4. 点“已联系”或“继续跟进”（约45秒）

让客户看到这不是一次性搜索结果，而是进入持续销售流程。

再演示“稍后提醒”，说明真实 Pilot 会服务端保存；当前 Demo 只在浏览器本地模拟。

### 5. 打开“公开依据不足”的商机（约1分钟）

重点说明：

- 即使客户医院关系很强，公开项目依据不足时，AI也不会硬生成建议；
- 这是产品与普通“AI招标总结”最大的可信边界之一。

## 推荐问客户的3个问题

演示结束后只问：

1. 如果每天早上自动给你5个这样的项目，你会不会看？
2. 如果把你现有医院关系和可做产品导入进去，哪些字段最重要？
3. 你最希望系统替销售少做哪件重复工作：找项目、判断值不值得跟、找产品/厂家、生成沟通话术，还是持续提醒？

## 不要在第一次 Demo 强调

- 数据源数量；
- 爬虫频率；
- Agnes 模型名称；
- API/Schema；
- SQLite/Serverless；
- 复杂后台配置。

第一次演示的判断标准不是“技术有多复杂”，而是客户是否明确说：

> 这个东西如果每天真能给我找到值得跟的项目，我愿意用。

## Demo 成功标准

至少满足以下任一项：

- 客户主动提出导入自己的医院关系/产品表；
- 客户愿意提供若干真实项目验证推荐结果；
- 客户愿意让销售团队试用；
- 客户主动询问正式版价格/上线时间。

如果只是觉得页面好看但没有上述行为，不算产品验证完成。
