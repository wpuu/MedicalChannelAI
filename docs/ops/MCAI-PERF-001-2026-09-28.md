# MCAI-PERF-001：快照内存复用 + AI 建议预生成

日期：2026-09-28

## 1. 快照内存复用（`web/api/_verifiedSnapshot.js`）

**问题**：`loadVerifiedSnapshot()` 有 12 处调用。每次都从 Neon 拉取完整 ~1.5MB JSONB，并做 3 次深度校验（本地实测 ~90ms CPU）；试用版 AI 路径每次请求还要调两次。

**修复**：
- 新增 `latestPublicVerifiedSnapshotIfChanged(knownHash)`：一次查询只比对 `snapshot_hash`（主键），hash 未变时 `payload` 返回 NULL，不再传输。
- 热实例 15s 内不访问数据库；超过 15s 只做 hash 探测；hash 变化才重新下载并完整校验。
- 并发冷启动共享同一次读取（in-flight 去重）。
- 每个调用方拿到独立的 `structuredClone` 副本，请求之间不会互相污染。
- 数据库不可用或 payload 校验失败时，回退行为与原来一致（Runtime Cache → Bundled）。

## 2. AI 建议预生成

**目标**：用户点“AI分析”时直接命中共享缓存（~0.4s），不再等模型。

- 新路由：`POST /api/ai/analyze?route=prewarm`，放在现有 analyze 函数内（Hobby 函数数量不变：11/12）。
  - `Authorization: Bearer <AI_PREWARM_TOKEN>`；未配置时回退到现有 `VERIFIED_SNAPSHOT_PUBLISH_TOKEN`。比对使用 timing-safe。
  - 候选顺序：Today 卡片优先，然后按 `priority.score` 取商机池前 N（默认 40，上限 100）；跳过 NOT_ELIGIBLE / BLOCKED_GROUNDING。
  - 每次调用最多生成 10 条（并行），返回 `remaining_miss_count` 供调用方循环。
  - 没有 durable cache 时拒绝执行（409），避免生成的结果无法共享。
  - 预生成请求不占用、也不受访客 IP 的频率限制。
- 新脚本：`web/pipeline/scripts/prewarm_ai_decisions.py`。循环调用直到剩余为 0；某一轮没有进展就停止；默认 best-effort（退出码 0），`--strict` 才会失败。
- **需要管理员手动添加的 workflow 步骤**（本次使用的 PAT 没有 `workflow` scope，无法修改 `.github/workflows/`）：把下面的步骤追加到 `regional-medical-refresh.yml` 和 `tianjin-medical-refresh.yml` 的 job 末尾（在 “Publish and verify optional external snapshot” 之后）。加上后，`test_prewarm_ai_decisions.py` 会自动检查它的位置和 `continue-on-error`。

```yaml
      - name: Pre-generate AI decisions for top opportunities
        # Best effort: users still get on-demand analysis if this is skipped.
        if: success()
        continue-on-error: true
        timeout-minutes: 8
        shell: bash
        env:
          AI_PREWARM_URL: https://medicalchannelai.vercel.app/api/ai/analyze
          AI_PREWARM_TOKEN: ${{ secrets.AI_PREWARM_TOKEN }}
          VERIFIED_SNAPSHOT_PUBLISH_TOKEN: ${{ secrets.VERIFIED_SNAPSHOT_PUBLISH_TOKEN }}
        run: |
          set -euo pipefail
          python3 web/pipeline/scripts/prewarm_ai_decisions.py --rounds 5 --limit 10 --max-candidates 40
```

**可选配置**：GitHub Secret `AI_PREWARM_TOKEN`（同时配到服务端环境变量）。不配也能用，会复用现有 publisher token。
