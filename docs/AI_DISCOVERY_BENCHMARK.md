# AI 商机发现：Agnes 影子挖掘与基准验证

## 目的

MedicalChannelAI 不把人工搜索到的商机直接做成产品数据。人工/确定性适配器已经核验过的样本只作为 **gold benchmark（已知答案）**，用于判断 AI 是否真的具备自主发现能力。

生产方向是：

1. 实时雷达由用户维护医院/机构和公开渠道，不维护人工挑出的具体商机；
2. Agnes 从本次真实抓取到的官方链接集合中自主挑出可能属于采购前期窗口的候选；
3. 模型只能引用输入中真实存在的 URL，编造 URL 会被程序拒绝；
4. AI 输出统一标记 `DISCOVERED_UNVERIFIED`，不能直接进入公开事实层；
5. 将 AI 发现结果与现有独立 VERIFIED 集合比较，计算“已知样本发现能力分”；
6. Agnes 找到而旧适配器没有找到的链接属于“新候选”，必须再走独立官方事实核验，验证通过后才能发布。

这意味着人工搜索的作用被限制在**测试和验收**，而不是成为未来数据生产方式。

## 实时雷达的渠道管理与缓存

实时 `/radar` 不再把医院数量写死在服务端。用户可以增加、修改、停用或删除医院官网、政府采购、公共资源交易、卫健主管部门等公开入口。初始 3 个医院入口只作为可删除的验证模板，不是预置商机结果。

每次点击“检查更新”都会先重新读取公开页面并计算链接集合指纹：

- 指纹未变化：复用已保存的上次 AI 结果，**不重复调用 Agnes**；
- 指纹变化：重新调用 Agnes；
- 用户修改渠道 URL/类型：旧扫描结果自动失效；
- 用户也可以显式“强制 AI 重分析”。

演示版先把渠道、扫描结果和渠道健康统计保存在当前浏览器。Pilot 账号数据库接入后再迁移到账号级持久化，不改变“先检查公开页面变化、再决定是否调用 AI”的逻辑。

渠道会累计技术/产出指标，包括扫描次数、AI 调用次数、缓存复用次数、连续失败次数、连续无候选次数。系统只给出“建议检查/低产出”提示，不自动删除渠道，避免把暂时没有商机的有效官方栏目误判为无用。

## 公开 URL 安全边界

因为实时雷达允许用户填写公开渠道 URL，服务端必须防止把它变成任意网络请求工具：

- 只接受 HTTPS；
- 拒绝 localhost、IP 地址、内网/保留地址解析结果；
- 跳转只允许同一官方主机的 `www`/非 `www` 变体；
- 限制页面体积和跳转次数；
- 候选链接仍必须来自本次实际抓到的同域官方链接集合。

## 当前基准分

`run_agnes_discovery_benchmark.py` 的发现能力分只评价 AI 商机挖掘器，不冒充整个产品评分：

- 75%：对独立 VERIFIED 已知样本的召回率；
- 20%：URL grounding，模型是否只使用真实官方候选链接；
- 5%：结构化响应有效率。

**召回率分母必须与本次 AI 真正看见的官方链接集合一致。** 历史 VERIFIED 记录如果已经离开当前官网列表、位于未抓取分页，或超出实时雷达本次 80 条分析上限，只保留为历史参考，不能拿来压低本次发现分。实时雷达的范围是 `CURRENT_ANALYZED_OFFICIAL_LINKS`；离线 benchmark 的范围是 `CURRENT_FETCHED_OFFICIAL_LINKS`。

这条规则避免为了演示制造高分，也避免因为拿“AI 根本没有看到的历史样本”做分母而制造假低分。

建议第一阶段门槛：

- 当前可见已知样本召回率 >= 85%；
- URL grounding >= 99%；
- 发现能力分 >= 85；
- 编造 URL 必须被程序 100% 拒绝；
- 新候选在独立核验通过前，永远不能作为“官方已验证商机”展示。

## 对老杨演示版的含义

演示版的“眼前一亮”不应来自预先塞进去几条人工找到的信息，而应来自一条可重复的链路：

**老杨选择要看的医院/渠道 -> 系统检查公开页面是否更新 -> Agnes 只在有新内容时分析 -> 官方证据核验 -> 判断这是前期窗口还是已经太晚 -> 结合客户产品/医院关系重排 -> 一键生成今天应该怎么跟。**

只有当候选实际来自 AI 影子挖掘并通过独立核验，UI 才允许显示“AI 情报雷达发现”。这样演示数据和未来正式产品使用同一套生产逻辑。

## 当前执行方式

离线能力测试仍可手工触发 GitHub Actions 工作流：`Agnes Discovery Shadow Benchmark`。该 benchmark 使用固定测试入口，目的只是保持可重复的能力基准；它不决定实时产品要扫描哪些医院。

工作流只读仓库、调用 Agnes、输出 7 天保留的 benchmark artifact；**不会修改 Production 数据，不会把 AI 候选自动写进公开快照。**

需要 GitHub Actions Secret：`AGNES_API_KEYS`。如果未配置，工作流直接失败，不能生成伪造评分。
