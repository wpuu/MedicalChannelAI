# AI 商机发现：Agnes 影子挖掘与基准验证

## 目的

MedicalChannelAI 不把人工搜索到的商机直接做成产品数据。人工/确定性适配器已经核验过的样本只作为 **gold benchmark（已知答案）**，用于判断 AI 是否真的具备自主发现能力。

生产方向是：

1. 系统只维护“官方来源入口/允许域名”，不维护人工挑出的具体商机；
2. Agnes 从官方索引页的真实链接全集中自主挑出可能属于采购前期窗口的候选；
3. 模型只能引用输入中真实存在的 URL，编造 URL 会被程序拒绝；
4. AI 输出统一标记 `DISCOVERED_UNVERIFIED`，不能直接进入公开事实层；
5. 将 AI 发现结果与现有独立 VERIFIED 集合比较，计算“已知样本发现能力分”；
6. Agnes 找到而旧适配器没有找到的链接属于“新候选”，必须再走独立官方事实核验，验证通过后才能发布。

这意味着人工搜索的作用被限制在**测试和验收**，而不是成为未来数据生产方式。

## 当前基准分

`run_agnes_discovery_benchmark.py` 的发现能力分只评价 AI 商机挖掘器，不冒充整个产品评分：

- 75%：对独立 VERIFIED 已知样本的召回率；
- 20%：URL grounding，模型是否只使用真实官方候选链接；
- 5%：结构化响应有效率。

建议第一阶段门槛：

- 已知样本召回率 >= 85%；
- URL grounding >= 99%；
- 发现能力分 >= 85；
- 编造 URL 必须被程序 100% 拒绝；
- 新候选在独立核验通过前，永远不能作为“官方已验证商机”展示。

## 对老杨演示版的含义

演示版的“眼前一亮”不应来自预先塞进去几条人工找到的信息，而应来自一条可重复的链路：

**AI 情报雷达自主发现 -> 官方证据核验 -> 判断这是前期窗口还是已经太晚 -> 结合客户产品/医院关系重排 -> 一键生成今天应该怎么跟。**

只有当候选实际来自 AI 影子挖掘并通过独立核验，UI 才允许显示“AI 情报雷达发现”。这样演示数据和未来正式产品使用同一套生产逻辑。

## 当前执行方式

手工触发 GitHub Actions 工作流：`Agnes Discovery Shadow Benchmark`。

工作流只读仓库、调用 Agnes、输出 7 天保留的 benchmark artifact；**不会修改 Production 数据，不会把 AI 候选自动写进公开快照。**

需要 GitHub Actions Secret：`AGNES_API_KEYS`。如果未配置，工作流直接失败，不能生成伪造评分。
