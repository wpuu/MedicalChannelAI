# MCAI-ZERO-TRUST-OWNER-DECISION-20260925

日期：2026-09-25  
性质：GPT-5.6 Sol High Owner 对 GPT-6 Sol《MedicalChannelAI 零信任冷启动产品方案》的裁决记录  
结论：ACCEPT WITH MODIFICATIONS / CHANGE

## 1. 总裁决

1. MedicalChannelAI 继续 KEEP，但只保留“公共医疗机会核验与行动路径”这一窄入口。
2. 不要求首次用户注册、提供企业资料、上传注册证/授权/报价/历史项目。
3. Medical Channel Hermes 保持独立；当前联合商业闭环仍为 NOT PROVEN。
4. Draft PR #23 继续 CLOSED / NOT MERGED；任何 Regional 白天增量只能进入既有 Incremental Collector / Queue / Tick / daily deep 架构。
5. 当前不启动 A↔B API / Skill，不合并仓库，不共享私有数据库。

## 2. 对 GPT-6 Sol 方案的接受项

接受 L0→L4 信任阶梯：
- L0：零输入公共价值；
- L1：一个低敏产品/品类词，可选厂家/品牌/型号/证号/UDI 精查；
- L2：仅围绕当前公告逐项“有 / 没有 / 不确定 / 跳过”，全部标为用户自报；
- L3：只有用户已从 A 获得价值并主动提出一条私有核验问题后，才考虑本地 Hermes；
- L4：跨真实项目出现复用需求后，才逐步形成局部 Product Identity Graph。

接受公开数据边界：
- 可证实官方公告、事件阶段、原公告时限、公开递交/报名路径、已知更正/终止、部分公开注册/UDI/历史结果；
- 不可据此证明客户授权、完整型号/配置符合性、企业资质、投标资格或中标概率。

## 3. 第一屏：修改 GPT-6 Sol 的排序

首访保持“无需输入也能看到价值”，但不把泛化 Top 5 作为唯一主入口。

推荐第一屏同时存在两条路：

A. 主路径：输入一个产品或器械品类（可选、免注册）
- 示例：胃镜、超声、SPECT/CT、血液分析仪；
- 只用于筛公开机会；
- 不要求公司名、证照、授权；
- 厂家/品牌/型号/注册证/UDI 放在后续“精确查公开产品”，不作为第一步。

B. 次路径：先看“今日已核实精选”
- 最多 5 条，不够就少展示；
- 不是全国 Top 5，不写“为你推荐”；
- 用于让零输入用户立即理解产品能做什么。

单条机会详情的主 CTA 固定为：
“看官方原文和行动路径”。

原因：目标用户往往已有标讯工具。泛化公开机会本身相关性太低；一个低敏产品词可以在不建立企业知识库的前提下立即形成个人相关性。

## 4. AI 行动分析：KEEP，但降级为表达层

“AI 判断投 / 观望 / 放弃”本身不是差异化。

公开竞品页面已经宣称：
- AI 主动精选；
- 投 / 观望 / 放弃；
- 项目研判；
- 竞对、报价、推送等能力。

因此 MedicalChannelAI 不把“AI 行动分析”作为核心护城河，也不突出“AI 更聪明”。

KEEP 的是受约束的公共行动卡：
1. 官网事实；
2. 事件阶段；
3. 各时间窗口分别是什么；
4. 今天实际还能做什么；
5. 官方入口在哪里；
6. 哪些条件未知；
7. 何时应暂不跟；
8. 最近一次官方核验时间；
9. 更正/终止后 fail closed。

公共 brief 可继续使用 opportunity_id + fact_hash + prompt_version 跨用户持久复用；个人产品词和 L2 自报不得进入公共缓存。

## 5. 当前最值得验证的差异化假设

不是：
- 标讯更多；
- AI 摘要更好；
- 有证号；
- 有中标历史；
- AI 会说“投 / 观望 / 放弃”。

而是：

“在不注册、不建立企业知识库、不上传私有文件的前提下，MedicalChannelAI 能否比用户现有工具更快、更少错地告诉他：这条公告到底处于什么阶段、今天还有没有入口、真正下一步是什么、哪些关键条件仍未知，并且在更正/终止后保持可追溯。”

这仍只是待验证假设，不是已证明的竞争优势或护城河。

## 6. 更好的真实演示样本

罗定公告可保留为跨地区结构演示，但不应默认作为老杨第一次 Demo 的主样本。

优先使用目标用户实际地区/产品的当日官方机会。

特别优先能暴露“窗口语义”的案例。例如 2026-09-25 查看天津的两个公开项目：
- 天津医院 SPECT/CT 项目：投标截止 2026-10-10，但招标文件获取期已于 2026-09-24 结束；
- 天津市肿瘤医院设备采购项目 BH-ZLYY2026837：投标截止 2026-10-12，但招标文件获取期也已于 2026-09-24 结束。

如果系统只显示“10 月还没截止”，就可能把“投标截止尚未来”误写成“新供应商今天仍可进入”。这类错误比摘要质量更能验证 MedicalChannelAI 是否真正有价值。

另一个可用反例是 2026-09-24 天津市肿瘤医院 B2 报告厅设备升级项目终止公告，用于验证“原机会必须被终止状态覆盖”，但它不是医疗器械主样本。

## 7. A 侧功能取舍

KEEP NOW：
- 官方机会与原始来源；
- 阶段、时限窗口、变更/终止；
- 当前已收录池；
- “今日已核实精选（最多 5 条）”；
- 一个低敏产品/品类词搜索；
- 公共事实 brief；
- opportunity_id / fact_hash / window_state / prompt_version；
- 既有 Incremental Collector / Queue / Tick / daily deep；
- 少量有原始依据的历史中标事实。

DEFER：
- 厂家/型号/证号/UDI 的大规模身份图；
- 全国扩源；
- 整省高频扫描；
- 自动提醒系统；
- 丰富企业画像；
- 复杂竞争图谱；
- PIG；
- Hermes 联通。

STOP NOW：
- 第二套 scheduler；
- “可投分”；
- 中标概率；
- 自动提交；
- CRM；
- 报价系统；
- 全自动资料包；
- 首页安装 Hermes；
- 以登录墙换取公共事实；
- 联系人/私人关系挖掘。

## 8. Hermes Sample Gate H0：旧版本正式 superseded

旧 H0 中以下硬前置正式废止：
- “必须先拿到 >=1 套真实客户已结束项目资料”；
- “必须先让客户交企业资料/注册证/授权/历史投标材料”；
- 以此作为 75126 的派发必要条件。

原因：这与新的零信任商业顺序冲突。尚未证明价值的软件不能把客户私有资料当第一张门票。

### 新 H0

75126 继续 DEFERRED。

只有出现以下任一需求信号后，Owner 才重新评估 75126：
1. 用户已经从 MedicalChannelAI 的 L0/L1/L2 获得实际价值，并主动提出一条具体私有核验问题，例如“能不能帮我核这份授权是否覆盖这个地区/型号/期限”；或
2. 已存在明确的近期 L3 受控演示承诺，且 Opus 5.5 / Hermes Owner 独立确认 75126 正是阻塞“一条公告 + 1–2 份文件”证据核验的最小技术缺口。

工程验证可以使用公开、仿真或经授权样本；不要求真实客户先交整套资料。

75126 如果未来恢复，其目的严格限定为：
“为 L3 一条公告 + 1–2 份本地文件提供可核对正文提取与证据锚点。”

不是：
- 完整私有资料平台；
- PIG；
- 全自动资料包；
- MedicalChannelAI 公共 Demo 的前置条件。

## 9. Joint Business Gate A 保持独立

完成 75126 永远不等于商业 PASS。

Stage 2B/3、PIG 深化、A↔B 联通和更大投入仍需真实商业证据，包括：
- 至少两家互不关联企业；
- 可核的真实行为；
- 至少一笔有金额/范围/交付约定的实际付款；
- 第二家至少出现可核预算审批动作；
- 工时/错误/复用率有真实对照；
- 无未经授权私有数据外发。

## 10. 7 天验证：接受方向，修改执行方式

7 天是验证 sprint，不是为了凑满人数的硬日历。

GPT-6 Sol 提出的 8 名陌生操作者可作为目标样本量，但不得把“7 天内找不到 8 人”误判成产品失败，也不得假定陌生经销商会配合。

按顺序验证：
1. 先用老杨/已有可信关系做流程和表达纠错，单列，不计陌生样本；
2. 若他真的执行了官网点击、转发给负责同事、要求换到自己的产品/地区，再通过其自然转发/引荐扩到实际操作者；
3. 同题对照现有工具，不接受“界面不错”“AI 不错”作为价值证据；
4. 只有出现二次行为后才测试“地区 × 产品线 × 已核更正/状态提醒”的小额人工/半人工试单；
5. 没有自然转发、没有二次动作、没有客观少漏/更快，则停止扩功能。

## 11. 老杨第一次 Demo

第一次不问公司资料。

优先流程：
1. 打开一条当天重新核过的目标地区真实机会；
2. 先让他看到“阶段 + 多个时间窗口 + 官方下一步 + 原文”；
3. 用一条“截止还在未来、但获取文件已经结束”或“刚终止”的案例证明系统不是简单看截止日期；
4. 如果他主动觉得有用，再让他说一个正在做的产品/品类词；
5. 立即筛该词对应的当前公开机会；
6. 最后只问：“这个你会不会点官网/转给负责的人/希望继续盯这个产品或地区？”

强信号：
- 自己点官网；
- 转发给负责同事；
- 指定产品/地区要求继续找；
- 后续回来查看变更；
- 产生明确报价/付款动作。

弱信号：
- 只说 UI 好看；
- 只说 AI 不错；
- 不点原文；
- 不要求自己的产品/地区；
- 无二次行为。
