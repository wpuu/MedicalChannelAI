# 医疗渠道资源网络效应规划

## 核心判断

MedicalChannelAI 未来最强的“借鸡生蛋”不是单纯聚合更多招采信息，而是把分散在不同用户手里的**医院/科室关系、厂家/品牌/产品能力、授权代理能力、租赁能力、投标执行能力**做成可组合的成交网络。

平台不取得或公开用户的具体关系资产；平台先只计算“哪些能力可以互补”，在双方明确同意后再分阶段披露合作所必需的信息。

因此网络效应来自：

`更多真实用户 → 更多经过确认的能力节点 → 更多可执行组合 → 更多成交结果 → 更多用户愿意维护能力数据 → 更强匹配`

而不是：

`更多用户 → 把更多人的客户名单放在一起卖`。

后者既不安全，也会迅速摧毁平台信任。

## 1. 资源图谱

### 医院侧资源节点

用户可以自愿维护：

- 医院；
- 科室；
- 关系强度；
- 是否愿意接受合作撮合；
- 可参与的合作类型，例如引荐、需求核实、院内流程协助、项目跟进；
- 最近确认时间。

医院关系必须继续遵守当前规则：**只有用户明确确认的私有关系才算关系，目标医院、公开联系人都不能自动转成关系。**

### 供给侧资源节点

用户可以自愿维护：

- 产品品类；
- 品牌 / 厂家；
- 是否正式授权代理；
- 是否仅能找厂家；
- 是否可联合其他渠道；
- 是否可租赁 / 垫资 / 售后 / 投标执行；
- 覆盖区域；
- 有效期与证明状态。

“代理某厂家”不能仅靠用户写一句话就等同于 VERIFIED。规划三级状态：

1. `SELF_REPORTED`：用户自报；
2. `EVIDENCE_PROVIDED`：用户提供授权/合作材料，但平台仅做资料存在性核验；
3. `PLATFORM_VERIFIED`：以后有明确人工/机构核验机制时再启用。

在没有核验能力前，产品里必须清楚显示自报状态，不能包装成平台背书。

## 2. 双盲组合匹配

公开商机进入平台后，先从公开事实提取需求能力：

- 地区；
- 医院 / 科室；
- 产品；
- 采购阶段；
- 时间窗口；
- 需要的执行动作。

然后匹配不同用户的互补资源。

典型组合：

### A 有医院关系，B 有厂家代理

A：能进入目标医院/科室，但没有对应产品。

B：有对应产品/厂家授权，但没有医院入口。

平台向两边分别展示：

- A 看到：“存在一个经过确认的供给方，具备当前项目所需产品能力；是否愿意发起合作？”
- B 看到：“目标区域存在一个经过确认的渠道协作方，具备目标医院侧资源；是否愿意合作？”

双方同意前：

- B 不看到 A 的具体联系人；
- A 不看到 B 的商业底价、客户清单；
- 双方都不能直接导出对方资源数据库。

### A 有厂家资源，B 有投标执行

厂家/代理不一定擅长标书、现场、保证金、租赁、售后。平台可组合第三方执行资源。

### A 在天津有医院关系，B 在北京有厂家全国总代

区域扩展后，厂家能力可以跨区域共享，而医院关系仍严格按区域/医院/科室控制披露。

## 3. 隐私保护式“能力供给信号”

其他用户看到的不是原始私有资料，而是聚合后的信号，例如：

- “天津 · 检验方向：存在 3 个可合作供给节点”；
- “该商机目前平台内存在医院侧资源 + 产品侧资源的完整组合”；
- “存在经用户确认的目标科室协作资源，最近 90 天内更新”；
- “存在 2 个自报授权代理节点、1 个可找厂家节点”。

默认不展示：

- 用户姓名；
- 电话；
- 医院内具体联系人；
- 私有备注；
- 厂家商务联系人；
- 底价；
- 未经授权的合同/证明原件。

## 4. 用户授权模型

每条私有资源至少有一个共享级别：

1. `PRIVATE_ONLY`：仅用于自己的个性化排序，不参加撮合；
2. `MATCHABLE_ANONYMOUS`：允许系统匿名计算互补匹配，但不披露身份；
3. `DISCLOSE_AFTER_MUTUAL_OPT_IN`：双方确认后可披露必要合作信息；
4. `ORG_SHARED`：未来企业组织内共享。

默认必须是 `PRIVATE_ONLY`。

不能把老用户已有关系在升级后自动改成可撮合。

## 5. 防绕平台机制

如果平台未来靠撮合赚钱，必须从架构上降低“A、B认识后绕过平台”的概率。

第一阶段不需要做重交易平台，但应预留：

- 平台内部合作意向；
- 双方 opt-in 记录；
- 分阶段披露；
- 项目协作房间 / 消息留痕；
- 合作状态；
- 谁提供了哪类资源的贡献记录；
- 成交结果双方确认；
- 未来可接服务费、成功费、托管结算。

不要一开始就把双方完整联系方式同时展示出来。

## 6. 网络效应评分

以后可以给每个公开商机计算两个不同指标：

### 用户个人可执行度

只看当前账号自己的资源。

### 平台组合可执行度

只输出匿名聚合指标，例如：

- `0`：平台内尚无互补资源；
- `1`：只有医院侧或产品侧一边；
- `2`：两侧资源齐全，但未互相授权撮合；
- `3`：存在双方允许匿名匹配的完整组合；
- `4`：已经形成合作组；
- `5`：已有同类合作成交记录。

这个指标不能反向泄露“具体是谁认识谁”。

## 7. 反馈飞轮

每次真实合作后，只沉淀结构化结果：

- 是否成功建立联系；
- 是否进入下一阶段；
- 哪类能力组合有效；
- 哪个时间窗口介入更有效；
- 是否成交；
- 用户对合作方的履约评价。

这些结果用于提高未来匹配，但不能把私聊内容或客户名单直接训练成公共资产。

## 8. 商业化路径

优先级建议：

1. **订阅费**：用户为持续公开情报 + 私有匹配付费；
2. **撮合服务费**：双方建立有效合作后收费；
3. **成交成功费**：只有平台确实参与撮合/协作链条时；
4. **企业席位**：一个厂家/渠道公司多个销售共享组织资源；
5. **验证服务**：以后对代理/授权/履约能力做独立核验。

不要把“出售医院关系数据”设计成收入项。

## 9. 实施顺序

### 当前 Pilot

继续保持完全私有：医院关系、科室关系、厂家/产品能力只用于当前账号。

### 第二阶段：资源标准化

- 给供给能力增加厂家/品牌/授权状态/区域等结构字段；
- 给每条资源增加共享级别；
- 默认 PRIVATE_ONLY；
- 不做跨用户展示。

### 第三阶段：匿名撮合

- 建立需求能力图谱；
- 建立匿名供给索引；
- 只返回“存在可合作节点”信号；
- 用户主动 opt-in 后才建立合作请求。

### 第四阶段：合作闭环

- 双方确认；
- 分阶段披露；
- 协作状态；
- 结果与评价；
- 再考虑收费。

## 10. 与区域公共情报层的关系

公共采集仍然是“一座城市统一跑一次，多用户共享”。

用户私有资源网络则是另一层：

`天津公共商机版本` → `匹配天津所有允许参与匿名撮合的私有能力索引` → `为每个用户给出个人可执行度 + 匿名平台组合机会`。

以后北京上线时，公共数据只新增北京区域采集；厂家/品牌供给能力可按其授权区域参与北京匹配，医院关系仍按具体医院/科室控制。

这使系统同时获得两种规模效应：

- **数据侧规模效应**：一个城市抓一次，所有用户共享；
- **渠道侧网络效应**：用户越多，可组合的医院侧 × 产品侧 × 执行侧路径越多。
