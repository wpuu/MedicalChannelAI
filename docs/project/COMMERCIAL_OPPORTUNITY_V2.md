# MedicalChannelAI 商业商机 V2 优化补充

> 状态：产品商业层设计补充，不阻断当前公开试用上线。
>
> 核心原则：继续坚持 Evidence first。AI 负责分类、关联、解释、排序建议和销售行动，不得创造医院采购事实、预算、采购计划、品牌装机或关系事实。

## 1. 产品重新定义

MedicalChannelAI 不应停留在“医疗招标/采购信息 + AI 总结”。

长期目标是：

> **比普通标讯平台更早发现需求萌芽，并把公开事实转化成“今天应该跟哪家医院、为什么、下一步做什么”。**

用户购买的不是信息数量，而是持续作战能力。

产品必须始终回答三个问题：

1. **哪里可能有钱？**——当前及未来值得调查的医院/项目/渠道机会。
2. **为什么值得我跟？**——公开证据、产品匹配、生命周期、竞争与执行条件。
3. **我下一步做什么？**——可以立即执行的销售动作，而不是泛泛建议。

如果一个新功能不能明显改善以上三项之一，默认不进入近期开发。

---

## 2. 商机阶段：从“公开招标”前移

建议将商业机会生命周期扩展为：

| 阶段 | 含义 | 产品价值 |
|---|---|---|
| 0 无信号 | 暂无可验证事件 | 不进入商机 |
| 1 需求萌芽 | 新院区、扩科、床位、专项资金、设备更新、学科建设等前置信号 | **最高长期价值** |
| 2 需求成形 | 预算、采购意向、论证、市场调研等 | 高价值 |
| 3 公开竞争 | 招标/比选已公开 | 当前核心 |
| 4 结果 | 中标/终止/失败 | 事实沉淀 |
| 5 装机后生命周期 | 耗材、试剂、维保、升级、替换 | **高复购价值** |

当前版本可以继续以阶段 2–4 为主上线；V2 数据建设重点逐步向阶段 1 和阶段 5 扩展。

### 阶段 1 的候选信号

- 新院区、扩建、搬迁
- 新科室、新中心、新学科
- 新增床位或诊疗能力
- 专项债、财政预算、设备更新资金
- 科室相关招聘/人才引进
- 医院等级/重点学科建设
- 新诊疗项目、新技术准入
- 基建改造导致的设备链需求
- 已知老设备进入合理更新周期（只能作为推测因子，不得表述为确定采购计划）

这些信号必须保留原始来源，并在 UI 中清晰区分：

- **已发生事实**
- **AI 推断的潜在需求**

绝不能把推断写成医院真实采购计划。

## 3. 四个优先产品能力

### 3.1 需求萌芽雷达

目标：在正式招标之前告诉销售“值得调查谁”。

输出至少包含：

- 医院/科室
- 已验证前置信号
- 相关产品类别
- 信号时间线
- 需求成熟度（建议采用“阶段/强弱”表达，而非伪精确概率）
- 为什么值得调查
- 下一步建议核实什么
- 所有证据链接

### 3.2 医院缺口地图

目标：回答“同类医院通常配置什么，而这家医院目前公开证据中还没有发现什么”。

必须采用保守措辞：

> “公开信息中暂未发现 / AI 推测的配置缺口”，不得等同于医院真实缺失或采购计划。

可使用的依据：

- 医院等级
- 床位与科室规模
- 同区域同等级医院配置
- 历史采购
- 学科建设
- 诊疗能力

价值：不是直接卖一个结论，而是给销售一个**值得人工核实的问题清单**。

### 3.3 装机后续雷达

将一次设备采购视为后续生命周期的起点。

建立：

`设备采购/装机 -> 试剂/耗材 -> 维保 -> 配件 -> 软件升级 -> 替换`。

适合 IVD、耗材依赖型设备、维保价值高的设备。

系统应记录：

- 已验证采购时间
- 品类/型号（仅有证据时）
- 供应商/中标企业（仅有证据时）
- 预计生命周期规则（规则/AI推断，明确非事实）
- 后续值得监控的事件类型

### 3.4 渠道战斗力指数

面向厂家回答：

> “我想进入某省/某品类，哪些经销商是真的卖得动？”

建议维度：

- 历史医院覆盖
- 品类覆盖
- 区域集中度
- 历史中标活跃度
- 客单价区间
- 品牌绑定度（仅基于公开事实推导）
- 最近活跃度
- 与目标产品的匹配度

避免把“出现过合作”夸大成“独家代理/深度关系”。

## 4. 从“一条线索”升级为“持续作战能力”

单独告诉用户一家医院名称容易产生“信息泄露悖论”：一旦把核心线索说清，用户可能已经获得主要价值。

因此 MedicalChannelAI 的长期收费对象不应是孤立线索，而是：

- 用户负责的医院池持续监控
- 产品能力与医院需求持续匹配
- 每日变化提醒
- 医院时间线
- 跟进状态
- 竞争/中标变化
- 渠道资源
- AI 下一步行动建议

即：

> **不是卖“某医院可能采购”，而是替销售持续盯住他负责的 50/100/500 家医院。**

这样用户离开系统会失去持续监控、历史、个性化排序和行动记录，而不只是失去一条公开信息。

---

## 5. 今日页目标：每天告诉用户“今天该干什么”

建议长期把“今日重点”从纯排序列表进化为：

### 今日销售作战简报

- 今日新增有效信号数
- 立即处理
- 本周调查
- 长期监控
- 已跟进项目的新变化
- 竞争/终止/延期等关键异动

单卡结构优先：

1. **一句话结论**：为什么今天值得看。
2. **事实证据**：发生了什么。
3. **与我有什么关系**：与产品/医院资源匹配。
4. **下一步动作**：建议核实、联系或准备什么。
5. **证据来源**：始终可点击追溯。

避免页面堆满“AI洞察”但没有可执行动作。

## 6. 北极星指标：有效惊喜率

除 DAU、注册、AI调用量外，新增产品核心验证指标：

> **有效惊喜率 = 用户看到的推荐中，“以前不知道，并且愿意进一步调查/联系”的比例。**

早期验证方式：

- 找真实医疗销售/渠道用户；
- 每人给 5–10 条机会；
- 逐条记录：已知 / 不知道但无价值 / 不知道且想跟；
- 优先优化第三类占比。

如果推荐很多但用户都“早知道”或“不值得跟”，说明数据源/前置事件/匹配模型需要回炉，而不是继续堆 UI。

建议同时记录：

- 推荐 -> 加入跟进率
- 推荐 -> 查看证据率
- 推荐 -> 标记已联系率
- 用户主动设置监控对象数
- 7/30 日返回率

## 7. 商机评分 V2：保留可解释性

现有 public score + private personalization 结构保留。

未来增加“前置信号”时，不建议直接输出“采购概率 86%”等伪精确数字。

更适合：

- 信号强度：弱 / 中 / 强
- 阶段：萌芽 / 成形 / 已公开 / 结果 / 生命周期
- 行动优先级：0–100（明确只是销售行动优先级）
- 证据完整度
- 产品匹配度

评分构成必须能够展开说明。

示意：

### 公共事实层

- 事件阶段与可行动性
- 时效
- 项目价值
- 产品明确度
- 多源信号一致性
- 信号新鲜度

### 用户私有层

- 用户产品匹配
- 用户医院/科室关系
- 渠道/供应/租赁执行能力
- 已有跟进状态

禁止将用户关系缺失解释为“没有关系”，也禁止 AI 凭空创造关系。

## 8. 数据图谱目标

长期底层逐步形成以下实体与关系，而不是只有公告卡片：

### 实体

- 医院
- 院区
- 科室/中心
- 厂家
- 产品/注册证/UDI
- 经销商
- 项目
- 品牌/型号
- 政策/资金/建设事件

### 事件

- 采购意向
- 市场调研
- 招标/比选
- 更正/终止
- 中标
- 建设/扩建
- 学科建设
- 设备更新
- 装机生命周期事件

基本链：

`原始来源 -> 结构化事实 -> 实体匹配 -> 时间线 -> 规则/AI推理 -> 商机解释 -> 用户行动`

AI 只能位于事实层之后。

## 9. 获客闭环：不要只做“有功能的网站”

MedicalChannelAI 上线后必须验证真实获客路径，而不是等待自然流量。

推荐的第一批验证：

1. 找 20 名医疗器械/IVD/耗材一线销售或渠道负责人。
2. 让其提供一个真实产品/品类和区域。
3. 每人生成 3–5 条经过证据验证的机会。
4. 不问“产品好不好看”，只问：
   - 有几条你以前不知道？
   - 有几条你愿意实际打电话/微信确认？
   - 如果系统每天自动继续找，你是否愿意继续用？
5. 记录失败原因。

推荐免费入口长期可以是：

> **“告诉我你卖什么 + 做哪个地区，我给你 3 条值得调查的真实机会。”**

核心价值不能只停留在三条名称；注册/付费后获得持续监控、证据时间线、个性化排序和行动历史。

## 10. 上线优先级：避免临门一脚重构

### 当前上线前：不阻断

保持当前 v0.4.x 主流程稳定：

- Evidence first
- 当前天津公开采购数据
- 移动端
- 今日重点/商机/跟进/资源
- AI决策合同
- 事实追溯

本文件不要求为了上述 V2 能力延迟当前上线。

### 上线后 P0（先验证钱）

1. 增加真实用户反馈字段：已知 / 无价值 / 想跟进。
2. 计算“有效惊喜率”。
3. 支持用户按产品 + 区域创建监控。
4. 把“下一步行动”强化到商机卡首屏。
5. 收集 20 名真实销售的失败样本。

### 上线后 P1（扩大差异化）

1. 前置信号数据源。
2. 医院事件时间线。
3. 装机后生命周期。
4. 医院缺口推测。
5. 渠道战斗力指数。

### 上线后 P2（形成护城河）

1. 多省覆盖。
2. 产品/注册证/UDI 与医院事件图谱。
3. 组织级 CRM/监控协作。
4. 竞争品牌与渠道网络。
5. 可配置行业/产品商机规则。

---

## 11. 一句话产品准则

> **标讯平台告诉销售“项目已经来了”；MedicalChannelAI 要逐步做到“钱还没完全长成项目时，就告诉销售该去调查哪里”，并持续陪他直到结果发生。**
