# 区域公共医疗情报架构

## 目标

MedicalChannelAI 的公共数据和公共 AI 工作按“区域 / 来源 / 商机版本”统一执行，不按登录用户重复执行。

用户打开产品时，只读取已经整理好的公共情报，再叠加当前账号自己的产品能力、目标医院、已确认关系、执行偏好和跟进状态。

因此成本主要随“区域数量、来源数量、真实变化次数”增长，而不是随“用户打开次数”增长。

## 三层边界

### 1. 公共情报层（所有同区域用户共享）

包含：

- 官方公开来源抓取；
- VERIFIED 事实抽取；
- 医院、科室、产品、金额、公开联系人、时间窗口；
- 商机生命周期；
- 当前公共优先级基础分；
- 每次公开事实变化的版本历史；
- 不含任何账号私有信息的公共 AI 解读。

公共层禁止包含：

- 用户医院关系；
- 用户产品能力；
- 用户目标医院；
- 用户跟进、备注、提醒；
- 任何可识别特定客户的内部昵称。

### 2. 私有匹配层（按账号计算）

包含：

- 产品能力匹配；
- 用户明确确认的医院 / 科室关系；
- 目标医院关注；
- 找厂家、联合渠道、租赁等执行能力；
- 个性化分数增量；
- 跟进、提醒、推荐反馈。

这一层优先使用确定性规则，不因为页面打开而调用 AI。

### 3. 私有 AI 层（只有明确需要时调用）

只有“结合当前账号私有资源生成专属打法”等无法由确定性规则满足的请求，才进入私有 AI。

私有 AI 结果不得共享给其他账号。可按：

`user/org + opportunity fact hash + private profile version + prompt version`

做持久缓存。

## 区域采集周期

天津 Pilot 采用如下目标节奏：

- 官方列表 / 索引：每 60 分钟扫描一次；
- 新 URL：立即进入详情 VERIFIED 验证；
- 已知 URL：只有内容指纹 / ETag / Last-Modified 等表明可能变化时优先重抓；
- 仍处于行动窗口的重点公开机会：允许每 4～6 小时做一次保守复核；
- 截止倒计时：根据已 VERIFIED 事实实时计算，不为倒计时重复访问官网；
- 深分页 / 历史补洞：每天一次；
- 来源异常：fail-closed，保留最后一个正确公共版本，不发布半验证状态。

60 分钟是区域发现周期，不等于每 60 分钟把所有详情页全部重抓一次。

以后增加北京等区域时，增加独立 `region_code` 配置、来源集合和采集游标；用户访问不触发区域采集。

## 公共数据版本

每个公开商机有稳定 `opportunity_id`。

公共数据库至少保存：

1. `public_opportunities`：当前最新 VERIFIED 版本；
2. `public_opportunity_versions`：每次事实真正变化后的不可变版本；
3. `public_collector_runs`：每轮区域 / 来源采集结果；
4. `public_ai_briefs`：按公共商机版本共享的公共 AI 结果。

只有 fact hash 改变才创建新版本。仅仅“本轮又看到了同样内容”只更新 `last_seen_at`，不制造伪版本。

详情页后续提供“公开信息更新记录”，由版本 diff 确定性生成，例如：

- 报名截止时间变化；
- 产品清单增加 / 删除；
- 联系人变化；
- 预算变化；
- 生命周期从市场调研进入采购 / 更正 / 终止。

不能为了好看让 AI 猜测“发生了什么变化”。

## 公共 AI 缓存

同一商机、同一 VERIFIED 事实版本、同一行动窗口状态下，公共 AI 结论只生成一次。

推荐缓存键：

`opportunity_id + fact_hash + window_state + brief_type + prompt_version`

公共 AI 可以输出：

- 公开事实摘要；
- 当前介入阶段解释；
- 仅基于公开事实的风险；
- 通用下一步动作；
- 仅引用公开联系人和公开依据的首轮联系建议。

以下内容不能进入公共 AI：

- “你认识这家医院的人”；
- “你有某厂家授权”；
- “你的渠道能做”；
- 任何账号私有事实。

这些只能由私有匹配层 / 私有 AI 处理。

## 今日重点数量

产品概念统一叫“今日重点”，而不是把 Top5 写死成产品名称。

- 默认：5 条；
- 允许账号设置：3 / 5 / 8 / 10 / 15；
- 只控制首页展示数量；
- 不裁剪完整商机池；
- 不改变公共数据；
- 不改变公共 AI 缓存；
- 也不应该让产品 / 关系等私有 AI profile version 失效。

显示偏好独立存储，不与业务执行偏好共用更新时间。

## 用户请求路径

正常打开“今日”时目标路径：

1. 读取区域公共当前商机；
2. 读取已经存在的共享公共 AI（若有）；
3. 读取当前账号私有资源 / 跟进；
4. 本地或服务端确定性计算个性化排序；
5. 按账号 `today_limit` 返回今日重点；
6. 不触发官网采集；
7. 不因为查看页面重复调用公共 AI。

## 第一阶段边界

先把天津这套公共层跑通，再复制区域配置到北京。

当前不为了全国覆盖提前做复杂多租户大平台；但表结构和缓存键从现在开始必须带 `region_code` / 商机版本，避免以后重新推倒。
